# Employee Dashboard

A client-side dashboard built with AG Grid and React for the FactWise frontend assignment.

Live demo: _add link after deploying_

## Running it

```bash
npm install
npm run dev
```

Opens on http://localhost:5173.

```bash
npm run build     # production build
npm run preview   # serve the build
```

## Stack

- React 19 + TypeScript
- Vite
- AG Grid Community 36 (client-side row model)
- Tailwind CSS 4

No component library, no state management library, no backend. The grid holds the view
state and the grid API is the source of truth for anything derived from it.

## What it does

The provided 20-row dataset is loaded unchanged from `src/data/employees.json` and
rendered into 13 columns.

- Sorting on every column, multi-column with shift-click
- Per-column filters: text, number and date variants depending on the field
- Quick search across all columns including the skills array
- Column resize, reorder, pin, and show/hide from the toolbar
- Pagination with a page size selector
- Row selection
- CSV export that respects the active filters and hidden columns
- Reset that clears search, filters, sort, column state and selection

Four KPI cards sit above the grid. They are calculated from the rows that survive the
current filters, not from the raw dataset, so filtering to Engineering moves them from
20 employees / $87,950 / 217 projects / 19 of 20 active to 6 / $104,333 / 80 / 6 of 6.

## Handling the data

Four of the fifteen fields need more than a plain column definition.

**hireDate** arrives as a string (`"2021-03-15"`). A `valueGetter` converts it to a `Date`
so the date filter works and sorting is chronological rather than alphabetical, and a
`valueFormatter` handles the display.

**skills** is an array, which AG Grid cannot sort, filter or search on its own. There is a
cell renderer for the chips, plus `filterValueGetter`, `getQuickFilterText` and a
`comparator` that flatten it to a string. Searching "React" finds John Smith.

**manager** is null for the five department heads. Those render as an em dash with a
tooltip rather than an empty cell.

**salary** and **performanceRating** are formatted through `valueFormatter` only. The
underlying values stay numeric so the number filters and sorting still behave.

One thing worth noting: inside `getQuickFilterText` the `params.value` is the *formatted*
value, not the raw one. Reading `params.data` instead avoids a class of bug where, for
example, the string `"false"` is truthy and every row reports itself as active.

## Scale

The brief asks for something that handles large data sets but supplies 20 rows, so there
is a row-count selector in the toolbar (20 / 1,000 / 10,000 / 50,000). The first 20 rows
are always the original records; larger sets are generated by varying the seed rows in
`src/data/employees.ts`. Header shows the generation time.

Measured on 50,000 rows:

| | |
|---|---|
| Row generation | ~70ms |
| DOM row elements | 22 |
| Search keystroke | ~16ms |
| JS heap | ~96MB |

What keeps it there:

- `columnDefs`, `defaultColDef` and every other grid config object are module-level
  constants, so they keep a stable identity across renders. Passing fresh objects makes
  AG Grid tear down and rebuild columns on every render.
- `getRowId` lets the grid track rows by id instead of recreating them.
- Quick search is debounced by 180ms and `cacheQuickFilter` is on. Without both, typing
  at 50,000 rows cost about 140ms per keystroke.
- KPI totals are accumulated in a single pass over the filtered nodes.
- Only the AG Grid modules the dashboard actually uses are registered, rather than
  `AllCommunityModule`. `ValidationModule` is registered in development only so its error
  messages are stripped from the production bundle.

## Layout

```
src
├── components
│   ├── cells          EmployeeCell, SkillsCell, StatusCell, RatingCell
│   ├── EmployeeGrid   grid setup and theme
│   ├── KpiCards       the four summary cards
│   └── Toolbar        search, row count, columns, reset, export
├── data               the supplied JSON and the dataset generator
├── grid
│   ├── columns.ts     column definitions
│   └── stats.ts       KPI calculation from filtered rows
├── types              Employee
└── App.tsx            layout and grid API wiring
```

## Notes

Row grouping with aggregation, the Set Filter, the tool panel sidebar and Excel export
are AG Grid Enterprise features. They would suit this dataset well, particularly grouping
by department, but they show a watermark without a licence so they were left out rather
than shipped unlicensed. With a licence key they are a `registerModules` call and a
`rowGroup: true` on the department column.

Styling uses the AG Grid Theming API (`themeQuartz.withParams`) rather than the legacy
CSS theme files, so the grid picks up the same palette as the rest of the page.
